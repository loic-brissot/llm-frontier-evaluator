## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
README.md is the first page a visitor sees, but today it reads as an operator manual: it opens with one sentence, then three raw series tables, a glossary, a prompt list, setup steps, and a repository layout table. Some text is stale (setup_run.py no longer writes workspace/prompt.txt).

Target order of README.md:
1. A hook paragraph: what the repository does (one model, one frozen prompt, one run, measured on how the model worked) and why (compare frontier models on long, data-heavy builds), with the credit to Charles de Lassence's benchmark. Then one or two screenshots of the most spectacular runs.
2. The comparison section, with self-explanatory column names in the style of bench.lassence.net: each metric column carries its unit and meaning (Tokens generated: thousands, reasoning vs visible; Model time: minutes generating, tools excluded; Tool calls: shell / files / visual checks / web, failures marked; Context re-read: millions of tokens from cache; Est. cost: USD at list price), so the separate glossary is no longer needed.
3. The prompts section.
4. How to launch your own run.

Architecture and operator details (repository layout, script roles, run id format, effort levels per harness, rules_version, isolation model) move to a new docs/architecture.md.

The comparison tables are generated by scripts/compare_runs.py --sync-readme and checked in CI, and the prompts list is checked under the exact heading ### Prompts, so the code, tests, and maintainer docs change together with the README.
